# TC-02 — Context manifest and coverage, shadow only

TC-02 explains the context that already existed at the TC-01 baseline. It does not
construct, filter, reorder, summarize or dispatch executor input. Manifests are
derived, non-operational and `authoritative=false`.

## Model

The practical unit is an existing structured context field. `inputs`, current
`state`, previous material result and its strict result are expanded one level
further because those structures expose task, evidence, findings and duplicate
artifact representations. Other values remain intact. A structure unit accounts
for keys, separators and braces, so unit bytes partition the existing default JSON
serialization exactly. TC-02 does not parse prose into an unbounded semantic graph.

Necessity and transport are independent axes:

- semantic necessity: `REQUIRED`, `CONDITIONAL`, `UNKNOWN`, `UNJUSTIFIED`,
  `NEEDS_CONTRACT_EVIDENCE`;
- transport form: `INLINE_REQUIRED`, `REFERENCE_CANDIDATE`, `DUPLICATED`,
  `DERIVABLE`, `UNKNOWN`.

Each justification names a schema rule, authority, contract, evidence obligation,
protective condition, explicit operation/input or review requirement. Generic
“relevant” labels do not count. `UNJUSTIFIED` means no justification was found,
never safe removal. `DUPLICATED` and `DERIVABLE` describe representation and can
still carry required meaning.

Dependency types are bounded to `REQUIRES`, `CONSTRAINS`, `EVIDENCE_FOR`,
`DERIVED_FROM`, `SUPERSEDES`, `INFORMS`, `PROTECTS`, `INVALIDATES` and
`AUTHORIZES`. Lists and hashes are sufficient; no graph service exists. Cycles in
unit derivations fail validation.

Exact/structural duplication requires equal material values and equal authority
class. Empty/scalar coincidences do not qualify. Parsed JSON equal to the original
artifact is structural duplication. Similarity is never used. Cross-execution
repetition is reported separately and grants no removal permission.

Derivability requires deterministic inputs, a versioned rule, reproducibility and
an equality oracle. “An LLM could infer it” fails the guard. Reference candidacy
requires stable identity, version, valid digest, read permission, matching scope
and an authorized fetch mechanism. Current role executors have no expansion
mechanism, so Slice 002 produces zero reference candidates.

Protection coverage inventories authority, prohibitions, protected baselines,
acceptance criteria, Advisor-first, scope, destinations for Advisor, ZERO_COST,
blockers and previous adverse findings when applicable. Missing protection is a
material shadow finding. It does not block or permit a real dispatch in TC-02.

Coverage reports justified, unknown, unjustified and contract-evidence categories
by units and exact bytes. Source count is retained only as TC-01 observation and
is never treated as quality. Coverage can be high while a small protection is
missing; protection coverage is a separate acceptance oracle.

## Slice 002 findings

All four historical LLM contexts have byte-exact manifests. The known repetition
of contract, historical request/input and specification appears as deterministic
cross-execution repetition. Parsed previous artifacts are structural duplicates;
the final verification also repeats the local validation report. The final Advisor
context has five large units marked `NEEDS_CONTRACT_EVIDENCE`: the narrow final
question does not have an explicit selector contract proving their inline need.
They are not declared removable.

The preparation execution is a `DETERMINISTIC_REPLACEMENT_CANDIDATE` because its
literal transformation has an existing exact oracle. This is a finding only;
TC-02 does not replace or remove the historical LLM call.

`measured_bytes_reduction_potential` sums non-overlapping units whose current
transport is duplicated or deterministically derivable. It is not a safe-removal
set. The estimated token potential is `ceil(bytes/4)` and is not actual savings.
Cross-execution repetition is not added to that number because exploiting reuse
would require later contracts. Actual token and quota savings remain unavailable.

## Refutation

A small prohibition inside a large unit could be hidden by coarse granularity.
The separate protection inventory searches structured protective paths and a
small bounded set of explicit no-go markers. This improves detection but is not a
general semantic proof; unknown contract forms must be added through a versioned
rule, not guessed.

Equal content can have different authority. Duplication therefore requires equal
authority class, and tests reject collapsing different-authority values. This is
still only as correct as authority classification; unrecognized authority remains
unknown rather than duplicate.

An old adverse finding can disappear from a delta. TC-02 has no delta model and
examines the full persisted context; it inventories previous findings separately.
Future delta work must preserve that inventory and is not authorized here.

A valid hash can be inaccessible or out of scope. Reference guard tests require
permission, fetch mechanism and scope equality. A hash alone fails closed.

The selected granularity may hide mixed relevant/irrelevant prose. TC-02 does not
claim byte-level removal within such a unit. Finer parsing needs contract evidence;
otherwise the unit stays required, unknown or needs evidence.

Manifest metadata can exceed a small potential reduction. TC-02 manifests are
offline evidence and are never inserted into prompts. Any future operational
proposal must compare total transport including manifest overhead.

Coverage can be gamed by generic labels. The implementation uses enumerated,
versioned rules and exposes every reason/basis. Protection is an independent gate,
so inflating unit counts cannot hide a missing prohibition.

Rules use role/context schema and structured field meanings. Slice 002 supplies
the real forensic fixture, but duplication and guard algorithms are generic and
adversarial tests cover different authority, inaccessible/wrong-scope references,
unknown inputs, missing protection, cycles and failed derivation.

No material defect remained after refutation. Residual limits are explicit: no
prose-level completeness proof, no context expansion, no safe-removal decision,
no actual token savings and no operational use of coverage.

## Reproduction and boundaries

Run `python -m unittest discover -s tests -q`, then
`python -m tdt_control_plane.tc02_shadow --root ROOT --output-dir ROOT/evidence/tc02`.
The generator reads Slice 002 and TC-01 evidence, writes only TC-02 evidence and
verifies protected evidence hashes before/after. It opens no LLM session.

TC-01 semantics remain 4 LLM sessions, 1 deterministic execution, 5 recovered
results, zero recovery dispatches, and estimated 28,397 input / 4,928 output /
33,325 combined tokens. Actual runtime tokens and account quota attribution remain
`NOT_AVAILABLE`. Preflight remains FAIL at 8,004 against strict `< 8,000`.

TC-02 includes no context reduction, operational projection, deterministic role
replacement, budget enforcement, preflight change, Groq, A4, A5 or merge authority.

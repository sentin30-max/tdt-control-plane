# TC-01 — Token/context observability only

TC-01 adds derived, non-authoritative observations to the existing SQLite ledger.
It does not read telemetry during prompt construction, routing, authorization,
result validation or ingest. Telemetry failure is recorded as an event and cannot
turn a valid result into a failure. Identity/correlation conflicts in a direct
telemetry write fail explicitly.

The runtime prompt was moved without textual changes into `build_role_prompt` so
the exact bytes already sent can be measured without storing another prompt copy.
Tests compare the helper byte-for-byte with the pre-TC-01 expression. Context and
validated result bytes are measured from their existing objects. Token estimates
use `ceil(UTF-8 bytes / 4)` and remain `ESTIMATED`. Explicit counters are
`MEASURED` only when a runtime event supplies them. Missing counters remain null
and `NOT_AVAILABLE`; they never become zero.

Each observation is keyed by execution and attempt, bound to task, context digest,
result digest when present, revision, role and scope. Exact duplicate observations
are no-ops; a different observation for the same execution/attempt is a telemetry
contradiction. Multiple executor attempts therefore remain countable. Durable
spool recovery does not create another call or another usage observation.

The record distinguishes LLM and deterministic backends, model calls, failed calls
and pending/unreconciled usage. It also records source-reference count and existing
refs. Task complexity, full reconstruction, semantic reuse and material delta stay
`NOT_AVAILABLE` because current contexts contain no deterministic markers for
those claims. TC-01 does not add those policies.

Runtime input/output, cache and reasoning tokens are accepted only from explicit
runtime usage fields. The current historical records do not contain them. Context-
only actual tokens cannot be inferred from total runtime input tokens. Model
identity is recorded only if the runtime exposes it. Tokens and account quota are
separate; TC-01 performs no conversion, polling, scraping, enforcement or causal
attribution.

`python -m tdt_control_plane.tc01_shadow` reads the five preserved Slice 002
records, writes to a disposable local ledger and produces a new TC-01 evidence
file. It does not alter `evidence/slice002`, launch a role, call Groq or execute an
audit. The shadow result reconstructs four LLM sessions and one deterministic
execution; recovery reuses five records with zero new dispatches and zero usage.

TC-01 contains no budget enforcement, reservation, context pruning, manifest,
builder, delta context, Advisor reuse, context expansion, model selection, retry,
compaction or deterministic replacement of an existing role call. Those remain
outside this authorization. The Resistance preflight remains 8,004 against the
strict limit below 8,000.
